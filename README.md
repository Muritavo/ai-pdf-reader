# Research Workflow

A browser-based assistant for literature reviews. Import the references selected during screening, attach their full-text PDFs, and read each article with an AI model at hand to explain terms, answer questions and keep track of what was read.

> The interface is in Portuguese (pt-BR).

## Features

### Projects
- Keep several independent reviews side by side, each with its own references, notes, highlights and settings.
- Export a project to a JSON file and import it on another machine (PDFs stay on the machine they were attached on).

### Step 1 — Add references
- Import the CSV exported from your screening tool (e.g. Rayyan). The `key` and `title` columns are required; `year`, `journal`, `authors`, `doi` and `abstract` are read when present.
- Add references by hand when they are not on the CSV.

### Step 2 — Associate full text
- Attach a PDF to each reference (file picker or drag and drop).
- Reading progress per article, a mark for articles read to the end, and a shortcut back to where you stopped.
- Tag articles to organize them.
- Attach extra files (supplementary material, notes) to each document, kept in a folder of your computer on Chromium-based browsers or in the browser's own storage elsewhere.

### Reading a document
- High-resolution PDF viewer with a selectable text layer (and a manual offset for PDFs whose text layer is misaligned).
- Highlights and annotations, including across multiple lines, with a way to jump back to each one.
- Selecting text opens a menu with:
  - **Define** — an AI definition of the term, highlighted wherever it appears again (in this document or, if marked as global, in the others).
  - **Ask about this** — a question to the AI about the selected passage.
  - **Reference** — finds the reference cited at that point of the text, and lets you search for it.
  - **Highlight occurrences**, **Mark this location**, **Search on Google**.
  - Plugin actions (see below).
- A prompt bar to ask anything about the whole document, with a history of past questions and a helper that structures a question with you.
- Ask questions about figures and images on the page (e.g. turn a methods figure into a flowchart).
- Answers render Markdown, math (KaTeX) and Mermaid diagrams.

### Plugins
- **ChEMBL** — recognizes approved drugs in the selected text and shows their ChEMBL entry and structure.
- **UniProt** — recognizes human proteins and genes (including Greek-letter spellings such as IFN-γ) and shows their UniProt entry.

The lists these plugins match against are downloaded once and cached in the browser.

## AI backend

The app talks to any **OpenAI-compatible** chat completions server (`/v1/chat/completions`, streaming), such as a local MLX, llama.cpp, vLLM or LM Studio server. It uses the model the server reports as loaded.

- Default endpoint: `http://127.0.0.1:8000`, or the value of `VITE_AI_ENDPOINT` at build time.
- Other endpoints can be added and switched from the **AI status** panel in the app.
- Image questions need a model that accepts images.

No data leaves your machine except to the AI endpoint you configure and to the public ChEMBL / UniProt APIs used by the plugins.

## Getting started

Requirements: [Node.js](https://nodejs.org/) 20+ and an OpenAI-compatible AI server.

```bash
npm install
npm run dev
```

Then open the URL Vite prints.

If a local certificate is placed in `.cert/` (`cert.pem` and `key.pem`, e.g. made with [mkcert](https://github.com/FiloSottile/mkcert)), the dev server runs over HTTPS; otherwise it uses plain HTTP.

### Scripts

| Command | What it does |
|---|---|
| `npm run dev` | Starts the dev server |
| `npm run build` | Type-checks and builds to `dist/` |
| `npm run preview` | Serves the built `dist/` |
| `npm test` | Runs the Playwright end-to-end tests |

### Desktop and Android apps

Packages for macOS, Windows, Linux and Android are built from the [`RELEASE/`](RELEASE/README.md) folder.

## Data storage

Everything is kept in the browser of the machine you use: references, highlights and answers in `localStorage`, PDFs and plugin lists in IndexedDB / the browser file storage. Clearing the site data erases them, so use **Export** to keep a backup.
